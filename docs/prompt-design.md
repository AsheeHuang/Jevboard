# 給 Jev 的 prompt 與判斷規則

Jev 只有「在固定選項中選一個」的題型（[Choice](https://docs.typesafe.ai/primitives/choice)），不生成文字。整個設計都圍繞一件事：把「這個位置該選哪個同音字」變成「這幾個句子版本哪個才對」。程式碼在 [Program.cs](../src/Program.cs) 的 `BuildQuestions`、`Propose`、`Refine`、`PairStage`、`AskBothOrders`。

## 請求結構

一個 `POST https://api.typesafe.ai/v1/systemone`，`model` 為 `jev-latest`，逾時 8 秒，不重試。

**state**（整個請求共用）：

```
這句話前面已輸入的文字：「<游標前最多 40 字的已定稿文字>」      ← 讀得到才附
使用者正在用注音輸入法打一句台灣繁體中文。注音輸入法只能靠讀音猜字，常把同音的詞選錯。
每一題的所有選項讀音完全相同、只有用字不同，請依整句的語意判斷哪一句才是使用者想打的。
```

state 刻意**不放目前轉換出來的句子**。第一版放了，Jev 就定錨在原句，每題都選跟 state 一模一樣的版本。

同樣的道理，「前面已輸入的文字」絕不能含組字本身。記事本這類 RichEdit 欄位用 `WM_GETTEXT` 讀到的游標前文字會連未定稿的組字一起傳回來，程式曾經就這樣把「想在去一次芮氏」當前文送出去：同一句、同樣的候選，不帶前文時「瑞士」拿 0.98，帶了只剩 0.55，第二輪 0.44，在記事本裡怎麼按都過不了門檻。現在前文一律取組字**之前**的已定稿文字：TextPattern 讀到的優先；觸發時讀到的文字若以組字結尾，就把那段剪掉（`Candidates.ContextFor`）。

**questions**：每個位置一題，id 為 `p<位移>`：

```
instructions: 以下各句只有第 N 個字開始的詞不同（讀音相同）。哪一句語意正確、通順，
              且用的是台灣常用的詞？不要選簡體字、生僻字或不成詞的組合。
criteria:     c1 = 把該位置換成輸入法第 1 個候選後的整句
              c2 = …第 2 個候選…
              …
```

選項 id 的數字就是該候選在輸入法當頁的順序。第一版的選項是單一個字，模型比較整句版本的表現明顯較好。

## 選項的取捨

- **合併同句**：換出同一句的候選只保留第一個 id（「由於」和「由」換出的都是原句）。不合併時「維持原句」的機率會被拆成兩份，判斷失真。
- **維持原句的選項**（`KeepId`）：與目前句子相同的那個選項。目前句子從編輯器讀到時它可能不是 c1（清單第 1 項「藥」、句子卻是「要」）；目前的字不在第 1 頁時，加一個 id 為 `keep`、不對應按鍵的選項。
- **罕見字與簡體字不當替代選項**：單字替代候選必須在 Big5 常用區（0xA440–0xC67E），所以「懽」「儗」這類異體不會出現；多字詞候選（「蜚語」「流言蜚語」）允許含次常用字，但整個詞必須在 Big5 內，簡體的「办」「发」一律排除。目前轉換的候選不受此限。代價是不在 Big5 的單字（多為人名用字）不會被建議。
- **注音符號項**（清單最後的「ㄅㄟˇ」）與超出句尾的詞排除；剩不到兩個選項的位置不出題；未知字（空白、英文）的位置不出題。

## 正反序各問一次

Jev 對排在第一個的選項有明顯的壓低。把「戴」「帶」放在第 1、2 格問「約會要戴保險套」，第 2 格不管是哪個字都拿 0.9；放到第 2–4 格時機率才隨語意走；明確的句子（魷魚／由於）則不受位置影響。而「維持原句」又固定在第一個。所以每一題都在同一個請求裡再以反序多問一次（id 加 `m`），兩組機率取平均後才判斷。

## 採用規則

- 每個位置機率 ≥ 0.3 的替代字都列成一列（最多 2 列）。
- 只有排第一、機率 ≥ 0.5 且至少是「維持原句」兩倍的那個**預設勾選**；其餘是「可選」列，預設不勾，按該列數字鍵或點它才會改。原字 60%、另一字 40% 時，另一字會顯示但預設不改。
- 同一位置或範圍重疊的列互斥，勾一個自動取消另一個；多字詞覆蓋後續位置。
- 門檻依據：觀察到的誤判多落在 0.4–0.55 對 0.4–0.5 之間（遊於、權利、蘿），正確修正多在 0.6 以上。
- **不猜性別**：你／妳、他／她 之間的互換一律不提議（「我愛你」曾被改成「我愛妳」）；它／牠改成他／她仍允許，那是明確錯誤。

## 迭代與相鄰成對比較

- **迭代**：一句多個錯字時各題互相牽制（「留言妃與」要先把「與」改成「語」，「蜚語」才說得通）。每一輪把採用的修改套進句子後再問一次，最多 3 輪，沒有新修改就停。修改始終以原始組字的位移表示，套用時對得上輸入法的候選；某輪若選回原字，前一輪的修改會被撤掉。
- **相鄰成對比較**：「在是一次」這種兩個相鄰的字都錯、各自單獨換都不成句（再是一次／在試一次）的情況，第一輪一個都不會採用。這時多問一題整句比較，選項是原句、各位置最可能的替代字（機率 ≥ 0.15）單獨換、以及相鄰兩個位置一起換（再試一次），以同樣門檻勝出才採用。
- **輸入法認得的長詞不進成對比較**：少量選項的比較會放大模型偏見（曾把「羅密歐」改成「蘿蜜歐」），而輸入法以三字以上的詞轉換出來的位置幾乎不會是同音錯字。

## 設計過程中確認過的事

| 現象 | 處理 |
|---|---|
| state 含原句 → 每題都選原句 | state 只描述情境 |
| 選項是單字 → 判斷差 | 選項改成整句版本 |
| 由於／由 同句未合併 → 原句機率被拆 | 合併同句 |
| 建議「由于」「公办」「喜懽」 | 台灣用字指示 + Big5 過濾 |
| 「我愛你」→「我愛妳」 | 性別字不換 |
| 0.46 對 0.41 的雜訊被採用 | 門檻 ≥ 0.5 且兩倍 |
| 排第一的選項被壓低 | 正反序平均 |
| 留言妃與 卡在單題 | 迭代 |
| 在是一次 一個都不採用 | 相鄰成對比較 |
| 成對比較把羅密歐改壞 | 長詞不進成對比較 |

這些都在 [evaluation.md](evaluation.md) 的 111 句評估裡有對應案例。
