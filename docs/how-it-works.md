# 運作原理

本文說明 Jevboard 從雙擊 Caps Lock 到套用修改的每一步，以及這些做法背後的實測依據。最後附一句話從頭到尾的真實追蹤。

## 1. 熱鍵與適用判斷

- 低階鍵盤 hook（`WH_KEYBOARD_LL`，[Hotkey.cs](../src/Hotkey.cs)）只看 Caps Lock 與浮窗期間的按鍵。雙擊的定義是：兩次完整的按下／放開，間隔 350 ms 內；按住不放產生的 auto-repeat 不算第二次。
- 第一次按下先攔住；350 ms 內沒有第二次就用注入的按鍵重播一次原始的按下／放開，所以單擊的行為不變，只延遲 350 ms。程式注入的每個按鍵都帶 `dwExtraInfo` 標記，hook 看到標記就放行，不會把自己的按鍵當成使用者操作。
- 適用條件（不符合時原樣放行並在日誌記原因）：已啟用、前景不是 Jevboard 自己且有焦點視窗、鍵盤配置語言是 0x0404、該視窗的輸入法開著且在中文模式。英數模式一律放行，Caps Lock 不延遲；代價是組字以英文結尾、停在英數模式時不會觸發，要先按 Shift 切回中文。
- hook 回呼裡不做任何跨程序 UIA 呼叫（會卡住整個系統的鍵盤處理），只把工作丟回 UI 執行緒。

## 2. 找到候選窗

微軟注音的候選窗是 `TextInputHost.exe` 的 `Windows.UI.Core.CoreWindow`，位於 Windows 沉浸式 IME 的 z-band，`EnumWindows`、`EnumChildWindows`、`EnumThreadWindows`、`FindWindowEx`、UIA 根節點的子元素都列不出來，只有 `WindowFromPoint` 命中得到。程式用兩條路：

1. **UIA 事件**（主要）：候選清單每次打開，UIA 都會在該 CoreWindow 元素上送出 `StructureChanged(ChildAdded)`，事件帶著 `NativeWindowHandle`。程式啟動時用原生 COM `IUIAutomation` 訂閱整個桌面的 StructureChanged（[NativeUia.cs](../src/NativeUia.cs)），用快取的 ProcessId／ClassName／HWND 過濾出 TextInputHost 的 CoreWindow。不用 .NET 的 `System.Windows.Automation` 事件，因為它遇到某些程式送出的 runtimeId 為 null 的事件會在包裝層丟例外，整個程序被終止。
2. **游標附近 hit-test**（備援）：有系統 caret 的程式（原生 EDIT）用 `GetGUIThreadInfo` 的 caret 矩形，往下、往上探測少數相對位置，命中 CoreWindow 且 UIA 子樹含 `IME_Candidate_Window` 才算。Chromium 類程式沒有系統 caret，所以備援在那裡無效。

拿到 HWND 後，讀候選的方式是 `AutomationElement.FromHandle` → 找 `TEMPLATE_PART_CandidatePanel` → 一次帶快取的 `FindAll` 取得所有 `ListItem` 的名稱、可見與位置，依畫面上下順序排列。數字鍵 1–9 對應的就是這個順序（輸入法會依學習重排，所以每次套用前都重新讀）。

## 3. 打開候選

雙擊時清單若沒開，程式送一次 ↓ 並等候選窗出現（通常 40 ms 內）。游標停在英文或標點後面時 ↓ 看的是游標前那個字，開不了清單，就改按 Home 再 ↓ 從第一個字開；還是開不了就按 End 放回行尾，提示「沒有偵測到注音組字」。沒有組字時這些鍵只會移動游標，這是不要求使用者手動按 ↓ 的代價。

## 4. 逐字走訪

目標是取得組字裡每個位置的第 1 頁候選，以及整句的長度。唯一可觀察的訊號是「候選清單有沒有開、開在螢幕哪裡」。

```
Esc（關掉已開的清單）
Home
重複：
    ↓ → 等清單（最長 120 ms）
    有清單：記下候選與視窗位置；和上一個已讀位置的視窗位置相同 → 句尾，結束
            Esc 關清單
    沒清單：這個位置是空白、標點或英文（或已到句尾，分不出來）
            句首連續沒清單 → 當成前導未知字繼續；已讀過字之後遇到 → 進入反向階段
    →
反向階段：
    End
    重複：← 、↓ → 等清單
        有清單且視窗位置等於正向最後一個已讀位置 → 句尾位置確定，長度 = 該位置 + ← 的次數
        否則記下（有清單就記候選，沒清單就記未知字）
```

- 候選窗錨定在組字游標，位置隨游標逐字右移，所以「同一清單在同一位置再出現」能可靠判斷 → 已不再移動。
- 未知字各佔一個字，→／← 都會跨過它，所以句中夾英文或結尾標點都能正確對位，不用猜「連續幾個未知算句尾」。
- 每個未知位置要付一次等清單的逾時（120 ms），這是「沒有清單」沒有即時訊號的必然成本；按鍵之間不等待，輸入法會依序處理注入的按鍵。
- 讀一頁只需三次跨程序 UIA 呼叫（取根元素、找面板、帶快取的 FindAll），一個中文字約 0.1 秒。
- 使用者此時按任何鍵、切窗、焦點改變，都會把世代序號加一，走訪立刻中止，舊結果作廢。

清單開著時 Esc 只關清單；清單沒開時 Esc 會整句取消。程式只在確認清單開著時才送 Esc。

## 5. 目前句子

走訪拿到候選，但輸入法「目前選的是哪個字」從候選窗讀不到：清單的高亮永遠在第 1 項，第 1 項又是依字頻與學習排序，不一定是整句轉換用的字（ㄧㄠˋ 的清單第 1 項是「藥」，整句卻是「要」）。所以程式優先從編輯器讀：

- **UIA TextPattern**（Chromium、Electron、WPF、VS Code、Obsidian 等）：未定稿組字就在文字裡。走訪結束時游標在句尾，讀「游標前的文字」，最後 L 個字就是組字（L 是走訪算出的長度）。每個可讀位置的字必須是該位置某個候選的首字才採信，否則表示讀到的不是組字（例如只給已定稿文字的編輯器），退回重建。這條路同時得到真正的空白、英文、標點，以及組字前最多 40 字的已定稿文字當語境。語境只能是組字**之前**的文字：記事本（RichEdit）用 `WM_GETTEXT` 讀到的游標前文字含未定稿組字，照送會讓 Jev 定錨在原句（「想在去一次芮氏」的瑞士從 0.98 掉到 0.44），所以觸發時讀到的文字若以組字結尾會先剪掉。
- **重建**（原生 EDIT 等讀不到組字的欄位）：各位置候選第 1 項的第一個字拼起來。偶爾與實際不同，手動改過的字也看不到；套用時以字為準，不受影響。

## 6. 問 Jev

一個 HTTPS 請求、每個位置一題 Choice，選項是「換了該位置的整句」，正反序各問一次取平均。門檻、可選列、迭代、相鄰成對比較、罕見字與簡體字過濾、性別字不換等規則都在 [prompt-design.md](prompt-design.md)。回應裡 id 不在題目選項內或機率不合法的題視為無效；整個請求失敗（逾時 8 秒、401 等）時浮窗標示 AI 暫不可用，不改字。

## 7. 浮窗

自繪的 WinForms 視窗，`WS_EX_NOACTIVATE` 加上 `WM_MOUSEACTIVATE` 回 `MA_NOACTIVATE`，裡面沒有任何可取得焦點的控制項，所以顯示與點擊都不會離開編輯欄位。內容：標題、目前句、建議句（會套用的字藍底；有可選替代的位置點狀底線＋列號）、每處修改一列（實心徽章＝會套用、空心＝可選）、套用／取消按鈕與按鍵提示。位置在候選窗右側，超出螢幕時夾回工作區內。

## 8. 套用

- **貼上**（目前句子來自 TextPattern 時）：先確認候選清單已關，Esc 取消整個組字，把修正後的整句放進剪貼簿、Ctrl+V 貼上，再把剪貼簿原本的文字放回。幾乎瞬間完成；句子因此定稿。
- **逐處選字**（重建的目前句子）：每一處 Home、→ 到該位置、↓、在當下的清單裡以「字」找到它的數字鍵送出；清單變動找不到就停止並提示。整句保持未提交，輸入法會從這些選字學習。
- 套用前再次確認前景視窗與焦點都沒變；期間任何按鍵都會中止。

## 9. 取消與世代

每次觸發產生一個世代序號。走訪、Jev 請求、套用都帶著自己的世代；使用者按鍵、切窗、焦點改變、Esc 都會把序號加一並關閉浮窗，之後才回來的 Jev 回應或仍在進行的走訪都會發現序號不符而作廢。失焦時輸入法本身會把組字提交，這不是 Jevboard 做的。

## 10. 一句話的完整追蹤

輸入法把「想再去一次瑞士」轉成「想在去一次芮氏」（「芮氏」是詞庫裡的詞，如芮氏規模）。以下是 `tests\run-tests.ps1 -Whole` 印出的真實請求與回答（候選清單為評估用的固定資料）。

走訪得到的候選頁：

```
位置0 ㄒㄧㄤˇ  想 響 享 饗 餉 响
位置1 ㄗㄞˋ    在 再 載 栽 災 宰
位置2 ㄑㄩˋ    去 趣 覷 娶 闃
位置3 ㄧ       一次 一 衣 依 醫 伊        ← 輸入法把「一次」當一個詞
位置4 ㄘˋ      次 刺 賜 伺 廁
位置5 ㄖㄨㄟˋ   芮氏 瑞士 瑞 芮 銳 睿 叡 枘  ← 「芮氏」「瑞士」都是詞
位置6 ㄕˋ      氏 士 是 事 試 市 視 式 世
```

第 1 輪請求（state 共用；每題再以反序多問一次，略）：

```
state: 使用者正在用注音輸入法打一句台灣繁體中文。注音輸入法只能靠讀音猜字，常把同音的詞選錯。
       每一題的所有選項讀音完全相同、只有用字不同，請依整句的語意判斷哪一句才是使用者想打的。

p1 (keep=c1): 以下各句只有第 2 個字開始的詞不同（讀音相同）。哪一句語意正確、通順，且用的是台灣常用的詞？不要選簡體字、生僻字或不成詞的組合。
    c1=想在去一次芮氏 | c2=想再去一次芮氏 | c3=想載去一次芮氏 | c4=想栽去一次芮氏 | c5=想災去一次芮氏 | c6=想宰去一次芮氏
p3 (keep=c1): …第 4 個字…
    c1=想在去一次芮氏 | c3=想在去衣次芮氏 | c4=想在去依次芮氏 | c5=想在去醫次芮氏 | c6=想在去伊次芮氏
      （「一次」與「一」換出同一句，合併成 c1）
p5 (keep=c1): …第 6 個字…
    c1=想在去一次芮氏 | c2=想在去一次瑞士 | c3=想在去一次瑞氏 | c5=想在去一次銳氏 | c6=想在去一次睿氏
      （叡、枘 是 Big5 次常用字，不當替代選項）
```

第 1 輪回答（正反序平均）：p1 → 想再去一次芮氏 0.86（原句 0.06）；p5 → 想在去一次瑞士 0.98（原句 0.01）；其餘五題原句最高。兩者都通過「≥ 0.5 且是原句兩倍」，採用。「瑞士」是兩字詞，蓋掉位置 6。

第 2 輪：把採用的修改套進句子成「想再去一次瑞士」再問一次，這時維持原句的選項變成 c2（例如 p5：c1=想再去一次芮氏、c2=想再去一次瑞士，keep=c2）。沒有新修改，結束。

浮窗：目前「想在去一次芮氏」、建議「想【再】去一次【瑞士】」，列①「第 2 字 在 → 再 86%」、列②「第 6 字 芮氏 → 瑞士 98%」。按 Tab：有 TextPattern 的編輯器會 Esc 取消組字、貼上「想再去一次瑞士」；否則 Home → ↓ 選「再」、Home →→→→→ ↓ 選「瑞士」、End。
